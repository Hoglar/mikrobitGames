# CODAL V2 Driver Bindings

These bindings target the immutable revisions in [lock.json](../../../toolchain/lock.json), based on `codal-microbit-v2` v0.3.5. Changes to that runtime require reviewing these assumptions and repeating the hardware gates.

| Operation | Binding, status and timing behavior |
|---|---|
| Serial | `MicroBit::serial`, `setBaud(115200)`, `setRxBufferSize(128)`, `setTxBufferSize(128)`. Checked `DEVICE_OK`. CODAL allocates 129 bytes for each requested 128-byte usable ring. `read(ASYNC)` returns a byte or negative no-data; `send(..., ASYNC)` returns accepted bytes, zero when full or negative error. TX sends at most 32 bytes per service. The pinned UART driver has short internal hardware waits; actual maximum service gaps need measurement. |
| A/B | Active-low `io.buttonA/buttonB.getDigitalValue()` while temporarily locking each Button's pin binding, mirroring the driver's protected `buttonActive()`. The application's 20 ms debounce is the only source of wire counts; CODAL button events are ignored. |
| Logo | Public raw `logo.buttonActive()`. Calibration is started explicitly; snapshots wait for `TOUCH_BUTTON_CALIBRATING` to clear. Driver filtering/calibration precedes the application debounce and needs pulse tests. |
| Acceleration | Auto-detected board accelerometer, 8g range and 20 ms conversion period. The pinned target uses LSM303; the adapter sets its public enable status before configuration to bypass CODAL's unbounded first-sample spin. Checked `requestUpdate()` plus a data-update event within 100 ms establishes readiness. `getSample(SIMPLE_CARTESIAN)` copies coherent signed mg axes. It invokes another driver update internally; injected driver failures and physical signs still require board verification. Review this version-specific enable step when supporting another sensor/runtime. |
| Temperature | Adapter owns Nordic `NRF_TEMP` directly with BLE disabled. Starts a conversion and polls `EVENTS_DATARDY` across acquisitions, converts quarter-degrees to integer Celsius, requests another conversion after 1000 ms and invalidates a conversion pending for 100 ms. A cached value older than 1100 ms is invalidated before another conversion starts; an already-started conversion can retain it for less than 100 ms more. Recovery never re-ages an old cache/completion. Avoids CODAL thermometer's unbounded hardware spin. No other code may start the stock thermometer component. |
| Light | `DISPLAY_MODE_GREYSCALE_LIGHT_SENSE`, `NRF52LEDMatrix::status` readiness then `readLightLevel()` in 0..255. Checking readiness avoids the API's startup sleep. LED/light interference and hardware conversion cadence need measurements. |
| Microphone | Third `audio.rawSplitter` channel into `MicrophoneLevel`, a `LevelDetectorSPL` subclass. Input is explicitly demanded and idle timeout overridden; `listenerAdded()`/`getValue()` are avoided because they can block at zero level. Require data-valid and a callback within 100 ms. Normalize the driver's SPL using its configured 8-bit endpoints, clamp to 0..255 and round. The pinned target endpoints are 52 and 100. Take a short interrupt-protected copy of level/readiness/time. |
| Display | Copy row-major 0..9 pixels into `display.image`, rounded to 0..255. Read five-row system glyphs from `BitmapFont`; the core supplies fixed five-column glyphs, one gap and 50 ms column deadlines. No native asynchronous scroll is started. |
| Speaker | `audio.enable()`, speaker enabled, edge-pin output disabled, master volume 255. A persistent signed-16-bit, 44.1 kHz sine source feeds one mixer channel. A 256-entry lookup table and two 64-sample buffers are allocated once; per-command frequency/volume changes do not queue expressions or block on a synthesizer lock. The mixer itself still allocates managed output buffers. STOP silences this sole application sound source; microphone capture continues. |
| Clock | `system_timer_current_time()` milliseconds reduced to unsigned 32 bits. Application sleeps request 1 ms with a configured 1 ms scheduler tick. Requests do not establish measured service-gap bounds. |

Application sound aliases are static melodies in `core/protocol.cpp`, played at volume 128 with the same synthesis/cancellation path: `hello` = 440 Hz/100 ms, 660/100, 880/150; `happy` = 523/100, 659/100, 784/200. These are project-defined sounds, not CODAL sound-expression identifiers.

Invalid/unready/stale mandatory readings skip the complete snapshot. Commands and digital tracking remain independent. Startup configuration failures stop initialization with a panic rather than advertise degraded capabilities. Physical sensor signs, microphone update windows, maximum critical-section/service durations, audio quality, output cancellation delay and runtime heap/stack peaks are **unverified** until recorded hardware runs exist.
